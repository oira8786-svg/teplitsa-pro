# ТЕПЛИЦА PRO

Система управления тепличным хозяйством: производство, агрономия, склад, урожай, продажи, финансы и персонал.

**Целевая юрисдикция хозяйства:** Россия, Москва.  
**Валюта:** RUB. **Часовой пояс по умолчанию:** Europe/Moscow.  
**Клиенты:** Android, iOS и desktop (Flutter — целевой стек).

> Статус: начальный исходный каркас и схема БД. Это не развернутая система и не готовое мобильное приложение. Перед эксплуатацией обязательны настройка Supabase, применение миграций, проверка безопасности, тесты и сборка клиентов.

## Структура

- `supabase/migrations/` — версионируемые миграции PostgreSQL/Supabase.
- `docs/` — архитектура, безопасность и правила предметной области.
- `app/` — место для Flutter-клиента (будет добавлен следующим этапом).
- `tests/` — место для SQL/RLS и интеграционных тестов.

## Быстрый старт базы данных

1. Создать проект Supabase в контролируемой организации.
2. Установить Supabase CLI и выполнить вход.
3. Связать локальный проект: `supabase link --project-ref YOUR_PROJECT_REF`.
4. Проверить миграции на отдельном тестовом проекте.
5. Применить: `supabase db push`.
6. Проверить RLS и тесты до загрузки реальных данных.

Не помещайте ключи Supabase, пароли, токены и персональные данные в Git. В клиентском приложении допустим только publishable/anon key с корректным RLS; service_role key нельзя включать в приложение.

## Принципы

- Все бизнес-данные изолированы по `organization_id`.
- UUID создаются на клиенте или сервере; время хранится в timestamptz.
- Склад — журнал движений, а не редактируемое поле остатка.
- Проведённые финансовые и складские документы не удаляются; исправления оформляются сторно/реверсом.
- Офлайн-синхронизация должна сохранять конфликты для разрешения, а не молча перезаписывать данные.
- Нормы применения СЗР, срок ожидания и срок безопасного повторного входа берутся только из проверенной действующей инструкции для зарегистрированного применения в РФ.

## План ближайших этапов

1. Проверка и тестирование схемы и RLS.
2. RPC/транзакции для складских движений и реализации.
3. Персонал, задачи, начисления и журнал действий.
4. Агрономический календарь и каталог единиц.
5. Flutter UI, локальная SQLite и синхронизация.
6. Тестовая сборка Android/iOS/Desktop.

## Нормативная оговорка

Система помогает вести учёт и контроль, но не заменяет агронома, специалиста по охране труда, бухгалтерскую/кассовую систему и юридическую проверку. Перед использованием средств защиты растений проверяйте действующую регистрацию и регламент применения в РФ, культуру, защищённый грунт, норму, кратность, срок ожидания и ограничения доступа работников.
