# Применение серверных операций ТЕПЛИЦА PRO

## Перед началом

Инструкция рассчитана на тестовый Supabase, где базовые миграции 001–004 уже применены. Сначала сделай резервную копию тестовой базы и проверь, что подключён именно тестовый проект.

## Вариант 1 — Supabase CLI

Предпочтительный путь для нового проекта и дальнейшего сопровождения:

1. Проверь, что все файлы в `supabase/migrations/` присутствуют локально и имеют уникальные 12-значные версии.
2. Выполни `supabase link --project-ref YOUR_PROJECT_REF`.
3. Просмотри статус миграций.
4. Примени ожидающие миграции командой `supabase db push`.

Не переименовывай и не редактируй уже применённые миграции. Для исправлений создавай новую миграцию.

## Вариант 2 — SQL Editor

Если базовые миграции 001–004 уже применены вручную, можно скопировать весь `supabase/INSTALL_OPERATIONS.sql` в SQL Editor тестового проекта и выполнить один раз. Скрипт включает проверку принадлежности назначенного исполнителя тому же хозяйству и серверные RPC для агрономии, склада, урожая, продаж, оплат, расходов, задач и зарплаты.

Ручной запуск SQL Editor сам по себе не записывает версии в таблицу истории миграций Supabase CLI. Перед последующим использованием CLI обязательно сверить историю; не запускай `db push` вслепую.

## После установки

Скрипт не доказывает корректность RLS и бизнес-логики на реальных данных. Отдельно проверь роли, изоляцию двух хозяйств, параллельные списания, двойную продажу одного лота, переплату и ограничения задач. Не используй реальные сведения работников и покупателей до проверки требований 152-ФЗ и локализации персональных данных РФ.
