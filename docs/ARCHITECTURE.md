# Архитектура ТЕПЛИЦА PRO

## Целевой стек

- Flutter: Android, iOS, Windows, macOS, Linux.
- Supabase Auth: вход пользователей.
- PostgreSQL: единая база хозяйства.
- Supabase Storage: фотографии и документы (с приватными bucket и политиками доступа).
- SQLite/Drift на устройстве: офлайн-кэш и очередь исходящих изменений.

## Модель доступа

Пользователь может состоять в нескольких хозяйствах. Роль назначается в рамках членства в конкретном хозяйстве:
- owner — владелец;
- manager — руководитель;
- agronomist — агроном;
- warehouse — кладовщик;
- accountant — бухгалтер;
- worker — работник.

Не доверять роли, присланной клиентом. Проверять членство и роль в БД. Самостоятельное назначение роли owner запрещено.

## Изоляция данных

У каждой бизнес-таблицы есть organization_id. Связи между бизнес-таблицами используют составные внешние ключи (organization_id, id), чтобы исключить ссылки между разными хозяйствами. RLS включается на каждой таблице. SECURITY DEFINER функции должны иметь фиксированный search_path, минимальные права EXECUTE и тесты на обход RLS.

## Склад и деньги

Складские движения и платежи — неизменяемые записи. Исправления выполняются обратными движениями с причиной. Остаток считается суммой движений с учётом направления. Проведение продажи, резервирование урожая и списание должны выполняться одной транзакцией через проверенную серверную функцию, а не несколькими независимыми запросами клиента.

## Офлайн

- Каждая запись получает UUID.
- На клиенте хранится локальная копия и outbox.
- Событие имеет client_created_at, server_created_at, sync_status и idempotency_key.
- Повторная отправка одного события не должна создавать дубликат.
- Конфликты показываются пользователю; для складских/финансовых документов запрещён last-write-wins.
- Удаления синхронизируются tombstone-записями.
- Серверное время является авторитетным для проведения финансовых и складских операций.

## Нормативные данные РФ

Для препарата хранить снимок проверенного регламента: регистрационный номер, статус/срок регистрации, культура, место применения (в том числе защищённый грунт), объект воздействия, норма и единица, кратность, срок ожидания, срок безопасного повторного входа, источник, дата проверки и проверивший сотрудник. Отсутствие подтверждённого регламента означает статус «требует проверки», а не разрешение к применению.
