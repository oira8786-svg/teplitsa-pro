# Статус разработки

Обновлено: 2026-11-12.

## Готово в репозитории

- PostgreSQL-схема хозяйства: организации, членство и роли, теплицы, зоны, культуры, сорта, партии, агрономические операции и проверка безопасности обработок.
- Подготовлены таблицы склада, движений, урожая, покупателей, продаж, платежей, расходов, сотрудников, задач, зарплаты, аудита, заметок и единиц измерения.
- Миграция 004 закрывает прямую запись через клиент в журнал складских движений, партии урожая, продажи, строки продаж, платежи, расходы, задачи, зарплату, агрономические операции и аудит до появления транзакционных RPC. Эти ограничения намеренные.\n- Подготовлена миграция 005 с RPC `create_agronomy_operation`: проверка роли owner/manager/agronomist, принадлежности партии/препарата хозяйству, типов препаратов и единиц измерения; атомарная запись операции и события аудита. Для химических и биологических обработок автоматически создаётся запись `needs_review`; сроки ожидания и повторного входа не выдумываются. Миграция 005 ещё требует ручного применения и проверки в тестовом Supabase.
- Flutter: регистрация/вход по email и паролю, создание хозяйства, выбор хозяйства и стартовая панель.
- Реализован экран «Теплицы и зоны»: просмотр активных теплиц/зон, добавление теплицы и зоны для ролей owner/manager.
- Добавлен экран «Культуры и партии» с вкладками: культуры и сорта, партии растений, каталог агропрепаратов/удобрений. Создание записей рассчитано на owner/manager/agronomist; окончательно проверить его нужно после установки текущей сборки на Android и тестовых записей в Supabase.\n- Добавлены экран агрономического журнала, формы записи полива/подкормки/обработки и подключение модулей «Полив и подкормки» и «Защита растений». Сохранение заработает только после применения миграции 005.
- В каталоге средств хранятся только описательные сведения и регистрационные реквизиты. Приложение не генерирует дозировки, нормы, сроки ожидания или повторного входа.
- Параметры Supabase передаются в сборку как клиентские значения; секретный service_role/Secret key в приложение не включается.

## Проверки тестового Supabase по предоставленным скриншотам

- Миграции 001–004 применены пользователем по порядку; Supabase SQL Editor показывал успешное выполнение после каждой. Миграция 005 подготовлена, но пока не применена.
- В схеме public было 26 таблиц, RLS включён на всех 26; запрос каталога политик показал 39 политик.
- В статической проверке открытых условий обнаружена политика measurement_units.units_read с USING (true). Это общий справочник единиц только для чтения авторизованным пользователям.
- Email Auth включён; пользователь сообщил о включении Secure password change и Require current password when updating.
- Пользователь проверил вход в приложение на Android тестовой учётной записью.
