# ФаёзАгро — статус разработки

Обновлено: 2026-11-12.

## Реализовано в репозитории

- Русскоязычный Flutter-интерфейс «ФаёзАгро» с зелёной темой и Android-брендингом; авторизация Supabase, создание и выбор хозяйства.
- Теплицы и зоны.
- Культуры, сорта, партии растений и каталог агропрепаратов.
- Агрономический журнал и календарь плановых дат.
- Склад: склады, позиции, поступления, расходы/списания и расчёт остатка.
- Урожай по партиям, покупатели, продажи и частичные/полные оплаты.
- Расходы в RUB.
- Сотрудники, задачи, начисления и выплаты зарплаты.
- Заметки и базовая сводка отчётов.
- Android CI: анализ Dart, widget tests, сборка debug APK и публикация тестового релиза.

## Миграции и серверные операции

По текущей записи проекта, базовые миграции 001–004 ранее применялись пользователем в тестовом Supabase. Состояние удалённой базы в этом выпуске не проверялось.

- Исправлена коллизия версий миграций: проверка tenant integrity для назначенного исполнителя теперь имеет отдельную версию `202611110006`, следующую после `202611110005`.
- `supabase/INSTALL_OPERATIONS.sql` содержит транзакционные RPC, защищённое добавление составного FK исполнителя задачи и RPC проверки безопасности обработки.
- Прямая запись в складские и финансовые журналы остаётся закрытой; клиент должен вызывать узкие RPC.
- Для подтверждения безопасности обработки добавлен `verify_treatment_safety`: он требует статуса регистрации «действует», совпадения номера и срока регистрации РФ, версии этикетки, HTTPS-ссылки на источник, даты проверки и явно заданных интервалов до сбора/повторного входа. Интервалы сейчас поддерживаются только как фиксированное количество минут. Нулевой интервал допустим только как явно подтверждённое значение с этикетки; неизвестный или условный интервал (например, «до полного высыхания») должен оставаться непроверенным.
- Добавлена статическая проверка уникальности версий миграций, порядка разделов установочного SQL и наличия обязательных safety-проверок. Она не заменяет выполнение SQL в PostgreSQL и интеграционные проверки RLS.

## Осталось до пилотной эксплуатации

- Применить ожидающие SQL-миграции/RPC в тестовом Supabase и выполнить интеграционные проверки RLS и транзакций на двух отдельных хозяйствах.
- Проверить ограничения для всех ролей, включая прямые REST-запросы, а не только скрытие кнопок в интерфейсе.
- Добавить управление приглашениями, привязкой аккаунтов к сотрудникам и настройкой ролей.
- Расширить отчёты себестоимостью, оценкой прибыли, движением запасов и итогами начислений/выплат зарплаты; текущая сводка не является бухгалтерской отчётностью.
- Добавить UI для проверки безопасности обработки и показа источника/проверившего специалиста; серверный RPC пока не подключён к форме.
- Добавить приватное Supabase Storage для фото и документов.
- Реализовать локальную БД, outbox, идемпотентную офлайн-синхронизацию, разрешение конфликтов и резервное копирование.
- Проверить требования 152-ФЗ и локализацию персональных данных РФ до внесения реальных данных сотрудников/покупателей.
- Для СЗР использовать только действующую регистрацию и проверенную инструкцию РФ; не генерировать нормы, дозировки, сроки ожидания или повторного входа.
- Отдельно собрать и проверить iPhone и компьютерные клиенты.

До завершения проверок безопасности, резервного копирования, офлайн-синхронизации и требований РФ использовать только тестовые данные. Не считать текущую сборку production-версией.
