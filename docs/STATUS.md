# Статус разработки

Обновлено: 2026-11-11.

## Добавлено в репозиторий

- Базовая PostgreSQL-схема: хозяйства, членство и роли, теплицы, зоны, культуры, сорта, партии.
- Агрономические операции и снимок проверки безопасности обработок.
- Складские позиции и журнал движений, партии урожая, покупатели, продажи, платежи и расходы.
- Сотрудники, задачи, начисления/выплаты зарплаты, аудит, заметки и каталог единиц.
- Начальный Flutter dashboard shell на русском языке.
- Добавлена зависимость `supabase_flutter` и инициализация клиента через compile-time параметры `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`.
- Конфигурационные значения не зашиты в исходный код и не записываются в репозиторий.
- Миграция 004 с fail-closed ограничениями: прямые изменения складского журнала, продаж, урожая, платежей, расходов, задач, зарплаты и аудита заблокированы до появления проверенных транзакционных RPC.

## Не выполнено и не проверено

- Supabase Flutter client пока не запускался с реальными параметрами этого тестового проекта; сетевой доступ не проверен.
- Миграции не запускались на реальном экземпляре PostgreSQL/Supabase.
- SQL миграции 001–004 не прошли интеграционные тесты; hardening migration требует проверки на тестовой базе.
- RLS ещё требует комплексных тестов на каждую роль и межорганизационную изоляцию.
- Нет транзакционных RPC для проведения складских движений, резервирования урожая, продаж, платежей, расходов и задач. Поэтому часть операций намеренно закрыта для прямой записи.
- Добавлена миграция 005: назначенный на задачу пользователь должен состоять в той же организации; проверка активного членства остаётся задачей будущих RPC.
- Нет Supabase Auth UI, Storage policies, CI и автоматических тестов.
- Нет офлайн-БД, очереди синхронизации и разрешения конфликтов.
- Flutter-клиент не собирался на Android/iOS/desktop в этой среде.
- Нет импорта/актуализации государственного реестра и официальных регламентов применения СЗР.

## Блокирующие задачи перед пилотом

1. Применить миграции в правильном порядке на отдельной тестовой базе.
2. Исправить замечания SQL lint и выполнить интеграционные тесты.
3. Добавить атомарные server-side функции с проверкой роли, организации, остатков и аудита.
4. Проверить RLS для каждой роли; отдельно проверить невозможность доступа к данным другой организации.
5. Реализовать Flutter auth, выбор организации, формы и подключение данных.
6. Реализовать локальное хранение и синхронизацию.
7. Провести пилот с тестовыми данными; только после этого вводить реальные данные.

Не считать репозиторий готовой production-системой до закрытия этих пунктов.
