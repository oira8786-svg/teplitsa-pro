# Flutter-клиент

Flutter-клиент ТЕПЛИЦА PRO для Android с авторизацией Supabase и первыми хозяйственными модулями.

## Настройка подключения к тестовому Supabase

Из папки app установите зависимости командой flutter pub get.

При локальном запуске передавайте параметры через аргументы запуска. Publishable key — публичный клиентский ключ; в автоматической GitHub-сборке используются только Project URL и этот публичный ключ. Никогда не добавляйте в Git или клиентское приложение service_role / Secret key.

Windows PowerShell:
flutter run --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY

macOS / Linux:
flutter run --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY

Без параметров подключения приложение открывается в демонстрационном режиме.

## Авторизация и первое хозяйство

- Вход и регистрация выполняются по email и паролю.
- При включённом подтверждении email после регистрации нужно подтвердить адрес.
- После первого входа без членства приложение вызывает RPC create_organization; создатель становится владельцем.
- Если у пользователя несколько хозяйств, отображается выбор хозяйства.

## Подключённые хозяйственные экраны

- Теплицы и зоны: список активных теплиц/зон; добавление для owner/manager.
- Культуры и партии: культуры и сорта, партии растений, каталог агропрепаратов/удобрений. Добавление рассчитано на owner/manager/agronomist.
- Каталог агропрепаратов — справочник хозяйства, а не подтверждение регистрации или разрешения к применению. Нельзя полагаться на приложение для дозировок, сроков ожидания и повторного входа.

## Проверки и запуск

Выполнить flutter analyze, flutter test, затем flutter run.

GitHub Actions автоматически выполняет анализ, тесты и сборку Android debug APK. Свежий файл публикуется в Releases репозитория как предварительный тестовый релиз. Это не production-сборка.

## Важные ограничения

В базе пока намеренно запрещена прямая запись через клиент в складской журнал, урожай, продажи, платежи, расходы, задачи, зарплату, агрономические операции и аудит. Для них нужны проверенные транзакционные серверные функции. Не пытайся обходить эти ограничения прямыми запросами.

Пока не реализованы офлайн-БД и синхронизация, приватное хранилище фото/документов, полный набор транзакционных операций и импорт действующих нормативов РФ по средствам защиты растений. Используй только тестовые данные; не вноси реальные сведения работников и покупателей до отдельной проверки требований к персональным данным.

Актуальный перечень готового и незавершённого находится в docs/STATUS.md.
